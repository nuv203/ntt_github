## 1. Design Summary

The IP accelerates the **negacyclic Number Theoretic Transform (NTT)**, the core polynomial-multiplication primitive in CRYSTALS-Kyber and CRYSTALS-Dilithium (post-quantum cryptography). The final implementation is a Vitis HLS kernel targeting the Kria K26 SOM (`xck26-sfvc784-2LV-c`).

**Key outcomes:**

| Metric | Target | Achieved |
|--------|--------|----------|
| C-simulation | All tests pass | ✅ 35/35 PASS |
| Butterfly pipeline II | 1 | 2 (BRAM port constraint — see §4) |
| Fmax (HLS estimate) | 200 MHz | 136.99 MHz |
| LUT utilization | — | 17,173 / 117,120 (14.7%) |
| BRAM_18K utilization | — | 36 / 288 (12.5%) |
| DSP utilization | — | 54 / 1,248 (4.3%) |
| Max supported N | 4,096 (initial) | **1,048,576** via four-step algorithm |

Full synthesis tables and loop-level pipeline results are in [TESTBENCH_RESULTS.md](TESTBENCH_RESULTS.md), regenerated automatically by `uv run hls_flow.py --update-results`.

## 2. Deviations from Initial Plan

### 2.1 Barrett Reduction — Implemented (was "planned")

The initial plan noted that Barrett reduction was a future optimization to replace the naive `% q` hardware divider. Barrett reduction was fully implemented in the final design as `barrett_mod_mul()`. The reciprocal `mu = floor(2^62 / q)` is computed once per kernel invocation via a 63-cycle shift-subtract loop (`compute_mu()`), and `barrett_mod_mul()` uses four 32×32 partial products (each mapped to a DSP48) to reconstruct the high half of the 128-bit product without any hardware divide unit.

### 2.2 Four-Step NTT Added — Supports N up to 2^20

The initial plan only described the direct path (N ≤ TILE_N = 4,096). The final design adds a complete **four-step NTT path** for N > 4,096, enabling transform sizes up to N = 2^20 = 1,048,576. The four-step algorithm factors N = N1 × N2 and executes:

1. **Phase 1 — Column NTTs:** N1 NTTs of size N2, with psi pre-twist inlined during the strided DDR gather
2. **Phase 2 — Row NTTs:** N2 NTTs of size N1, with inter-stage twiddle applied during row load
3. **Phase 3 — Matrix Transpose:** via DDR scratch (psi_powers buffer reused after Phase 1 consumes all psi values)

All strided address arithmetic uses incremental counters (`addr += stride`) rather than `row * N1 + col` multiplies to avoid fabric multipliers on the critical path.

### 2.3 Memory Architecture Correction — LUTRAM, not all BRAM

The initial plan stated that `psi_local[]` and `tw_local[]` were `RAM_1P BRAM`. In the final design they are bound to **LUTRAM** (`impl=LUTRAM`) for lower read latency during random butterfly accesses. Only the working coefficient buffer `tile[]` uses block RAM (`RAM_T2P impl=BRAM`), which is why synthesis reports 36 BRAM_18K (one 4096×32-bit array) rather than the 96 BRAM_18K that three BRAM arrays would require.

### 2.4 Interface Port Rename

The initial plan used `port=x` in AXI interface pragmas. The final implementation uses `port=data` (matching the function signature `ntt_t *data`). The `psi_powers` port is also non-const in the final design because Phase 3 reuses it as a DDR scratch buffer for the transpose.

### 2.5 Butterfly II=2, Not II=1

The initial plan targeted II=1 for the butterfly inner loop. The final implementation achieves **II=2**. The `#pragma HLS DEPENDENCE variable=tile inter false` pragma is correct (consecutive iterations access disjoint element pairs), but `barrett_mod_mul` has a minimum pipeline latency of 12 cycles. At II=1, 12 in-flight computations would require simultaneous BRAM access that the single RAM_T2P port cannot provide. Achieving II=1 would require cyclic partitioning of `tile[]` (e.g., factor=2) to add a second independent BRAM port.

### 2.6 Testbench is Fully Self-Contained — No External Files

The initial plan described loading test vectors from binary files (`x.bin`, `ref.bin`, etc.) generated by a Python oracle. The final testbench (`ntt_tb.cpp`) generates everything internally — NTT-friendly primes, primitive roots, twiddle tables, and a golden reference NTT — requiring no external files or Python dependencies for C-simulation.

### 2.7 Automated Build Script Added

A Python build script (`kernel/hls_flow.py`) was added that automates the full synthesis flow: setting up the Vitis environment (including Ubuntu 24 `libncurses.so.5` compatibility), running `vitis-run --tcl`, parsing `csynth.xml`, printing rich terminal tables, and writing `TESTBENCH_RESULTS.md`. Dependencies are managed via `uv` inline script metadata.

## 3. Final IP Interface

### 3.1 Function Signature

```c
void ntt_kernel(
    ntt_t       *data,        // in/out: coefficient array, batch×N elements
    ntt_t       *psi_powers,  // in: negacyclic twist table (non-const: reused as scratch)
    const ntt_t *twiddles,    // in: Stockham twiddle factors
    ntt_t        q,           // prime modulus
    uint32_t     batch,       // number of independent transforms (1..MAX_BATCH)
    uint32_t     N,           // transform size, power of 2
    uint32_t     logN         // log2(N)
);
```

### 3.2 AXI Interface Pragmas (from ntt.cpp)

```c
#pragma HLS INTERFACE m_axi port=data       offset=slave bundle=gmem0 depth=16777216 max_read_burst_length=256 max_write_burst_length=256
#pragma HLS INTERFACE m_axi port=psi_powers offset=slave bundle=gmem1 depth=1048576  max_read_burst_length=256 max_write_burst_length=256
#pragma HLS INTERFACE m_axi port=twiddles   offset=slave bundle=gmem2 depth=1048576  max_read_burst_length=256

#pragma HLS INTERFACE s_axilite port=data
#pragma HLS INTERFACE s_axilite port=psi_powers
#pragma HLS INTERFACE s_axilite port=twiddles
#pragma HLS INTERFACE s_axilite port=q
#pragma HLS INTERFACE s_axilite port=batch
#pragma HLS INTERFACE s_axilite port=N
#pragma HLS INTERFACE s_axilite port=logN
#pragma HLS INTERFACE s_axilite port=return
```

### 3.3 Port Summary

| Port | Bundle | Direction | Width | Description |
|------|--------|-----------|-------|-------------|
| `data[batch×N]` | `m_axi gmem0` | R/W | 32-bit/elem | Coefficients; overwritten in-place with NTT output |
| `psi_powers[N]` | `m_axi gmem1` | R/W | 32-bit/elem | Negacyclic twist table; reused as transpose scratch in four-step path |
| `twiddles[≤N2+N1+N]` | `m_axi gmem2` | Read | 32-bit/elem | Stockham twiddles + inter-stage factors |
| `q` | `s_axilite` | Write | 32-bit | Prime modulus |
| `batch` | `s_axilite` | Write | 32-bit | Number of transforms (max 16) |
| `N` | `s_axilite` | Write | 32-bit | Transform size (power of 2, up to 2^20) |
| `logN` | `s_axilite` | Write | 32-bit | log₂(N) |
| `return` | `s_axilite` | Read | ctrl | Done signal (`ap_ctrl_hs`) |

## 4. Final Architecture

### 4.1 Execution Paths

**Direct Path (N ≤ 4096):**

```
DIRECT_LOAD_PSI  — burst DDR → psi_local[] (LUTRAM), once per invocation
DIRECT_LOAD_TW   — burst DDR → tw_local[]  (LUTRAM), once per invocation

for each batch element b:
    DIRECT_LOAD  — burst DDR → tile[] (BRAM) + inline psi pre-twist
    sub_ntt()    — SUB_BIT_REV (II=3) + SUB_BFLY (II=2) × logN stages
    DIRECT_STORE — burst tile[] (BRAM) → DDR
```

**Four-Step Path (N > 4096, N = N1 × N2):**

```
FS_LOAD_TW_COL — burst DDR → tw_local[] with N2-point twiddles

for each batch element b:
    Phase 1 — Column NTTs (N1 transforms of size N2):
        for each column 0..N1-1:
            FS_GATHER_COL  — strided DDR read + psi pre-twist → tile[]
            sub_ntt(N2)
            FS_SCATTER_COL — strided DDR write from tile[]

    Phase 2 — Row NTTs (N2 transforms of size N1):
        FS_LOAD_TW_ROW — reload tw_local[] with N1-point twiddles
        for each row 0..N2-1:
            FS_LOAD_ROW    — burst DDR read + inter-stage twiddle → tile[]
            sub_ntt(N1)
            FS_STORE_ROW   — burst DDR write from tile[]

    Phase 3 — Transpose via DDR scratch:
        FS_TRANS_LOAD/WRITE_SCRATCH — row-major → psi_powers[] (scratch)
        FS_TRANS_FROM_SCRATCH       — copy transposed data back to data[]
```

### 4.2 On-Chip Memory

| Array | Size | Type | Notes |
|-------|------|------|-------|
| `tile[TILE_N]` | 4096 × 32b | **RAM_T2P BRAM** | Working buffer; true dual-port for butterfly read+write |
| `tw_local[TILE_N]` | 4096 × 32b | **LUTRAM** | Twiddle cache; lower latency than BRAM for random reads |
| `psi_local[TILE_N]` | 4096 × 32b | **LUTRAM** | Twist table cache (direct path only) |

### 4.3 Barrett Modular Multiplication

```
barrett_mod_mul(a, b, q, mu):   PIPELINE II=1, LATENCY min=12 max=18
compute_mu(q):                  PIPELINE II=1, 63 iterations (shift-subtract)
```

`mu = floor(2^62 / q)` is computed once per kernel call. `barrett_mod_mul` uses four 32×32 DSP48 partial products to reconstruct the high 64 bits of `a*b*mu`, extracts the quotient estimate, and applies ≤2 conditional subtracts.

### 4.4 Pipelining Results

| Loop | Directive | II Achieved | Depth |
|------|-----------|-------------|-------|
| `COMPUTE_MU_LOOP` | `PIPELINE II=1` | 1 | 1 |
| `DIRECT_LOAD_PSI/TW` | `PIPELINE II=1` | 1 | 3 |
| `DIRECT_LOAD/STORE` | `PIPELINE II=1` | 1 | 16/3 |
| `FS_GATHER_COL` | `PIPELINE II=1` | 1 | 24 |
| `FS_SCATTER_COL` | `PIPELINE II=1` | 1 | 8 |
| `FS_LOAD/STORE_ROW` | `PIPELINE II=1` | 1 | 16/3 |
| `FS_TRANS_*` | `PIPELINE II=1` | 1 | 3–8 |
| `SUB_BIT_REV` | (sequential) | 3 | 4 |
| **`SUB_BFLY`** | `PIPELINE II=1` + `DEPENDENCE inter false` | **2** | **18** |

## 6. Verification

The testbench `ntt_tb.cpp` is fully self-contained and runs as part of `csim_design`. It covers:

| Test | Coverage |
|------|----------|
| `test_ref()` | Element-by-element match against reference NTT for all N and batch sizes |
| `test_lin()` | NTT linearity: `NTT(a+b) = NTT(a) + NTT(b) mod q` |
| `test_range()` | All outputs in `[0, q)` |

**35 test cases — all PASS.** Sizes: 256, 512, 1024, 2048, 4096 (direct); 8192, 16384, 32768, 65536 (four-step); PQC primes q=12289 (Kyber), q=8380417 (Dilithium).

To reproduce:
```bash
cd kernel
uv run hls_flow.py            # runs csim + csynth, prints tables
uv run hls_flow.py --update-results  # also writes TESTBENCH_RESULTS.md
```
